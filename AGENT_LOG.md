## 54. Что сделано

54.1. Причина: `NSGraphicsContext(bitmapImageRep:)` рисует в **пикселях** репозитория, а
      `materialized(scale:)` просил прямоугольник в **пунктах** — при scale 2 картинка заняла
      четверть битмапа (39 из 78 столбцов). `NSImage` при этом отчитывается полным размером, поэтому
      строка держала высоту, а картинка выглядела вдвое меньше. Баг принесён коммитом `375cdbe`
      (растеризация вне главного потока) и виден только на Retina.
54.2. Почему тесты не поймали: они проверяли `size`, `pixelsWide`/`pixelsHigh` и `draws`, но не то,
      что в битмапе вообще нарисовано целое изображение. Диагноз поставлен тестом на содержимое:
      прозрачные углы битмапа (alpha 0 у трёх из четырёх), затем профиль альфы по краям.
54.3. Правка: `context.cgContext.scaleBy(x: scale, y: scale)` перед `draw(in:)` — контекст начинает
      считать в пунктах. Новый тест `testRasterizedImageCoversTheWholeBitmap` обходит битмап и
      требует, чтобы закрашенные пиксели доходили до дальнего края; на старом коде падает с
      «it filled 39 of 78 columns», на исправленном — 6/6 в классе.
54.4. Проверки: preflight 0 error, полная `MaccyTests` — 84 теста, падают только известная средовая

63.2. Тест переписан на детерминированную проверку контракта: элемент без картинки не планирует

## 65. Личность подписи: самоподписанный сертификат вместо ad-hoc

65.1. Запрос: сделать подпись стабильной между сборками (самоподписанный сертификат вместо ad-hoc) и
      проверить, сохраняются ли тогда разрешения Accessibility и обновления Sparkle.
65.2. Разобрано, что именно ломает ad-hoc: designated requirement ad-hoc-билда — это `cdhash H"<хеш
      бинарника>"`, поэтому каждая пересборка для системы **другое приложение**. macOS хранит решения
      о приложении как требование и перепроверяет его при каждом доступе: в TCC это колонка `csreq`
      (декодировали настоящий блоб из `~/Library/Application Support/com.apple.TCC/TCC.db`:
      `identifier "com.apple.weather" and anchor apple`).
65.3. Сделан `scripts/create-signing-identity.sh`: самоподписанный сертификат «Maccy Local Signing»
      (10 лет, EKU codeSigning; openssl через конфиг — LibreSSL в системе не знает `-addext`), импорт
      в login-keychain с `-T /usr/bin/codesign`, чтобы не было запросов доступа к ключу. Доверие
      (`--trust`) опционально: подпись и `codesign --verify --strict` проходят и без него.
65.4. Проверено на двух **разных** бинарниках (Release и Debug), подписанных сертификатом: требование
      одинаковое — `identifier "org.p0deje.Maccy" and certificate root = H"5ae9dfa7…"`, и проверка,
      которую делает сама macOS (`codesign --verify --strict -R=<требование старой сборки>`), даёт
      MATCH; для пары ad-hoc сборок та же проверка даёт NO MATCH.
65.5. `scripts/install.sh` теперь выбирает сертификат (Developer ID → Apple Development → «Maccy Local
      Signing» → ad-hoc) и печатает требование с вердиктом «стабильно / только до пересборки».
      Приложение переустановлено уже с сертификатом: контейнер переиспользован, история 200 элементов,
      `~/Library/Application Support/Maccy` пуст, требование стабильное.
65.6. Про Sparkle: прежняя формулировка «ad-hoc билд Sparkle обновлять не станет» **опровергнута** по
      вендоренному исходнику (`Sparkle/SUUpdateValidator.m`): `if (passedDSACheck || passedCodeSigning)
      return YES;` — EdDSA-подписи архива достаточно, несовпадение подписей приложения допускается
      намеренно («allows key rotation without breaking chain of trust»). Единственная проверка, которая
      смотрит обе, отбраковывает лишь **невалидную** подпись новой сборки; сравнение team id в
      инсталляторе влияет только на атомарный swap. Формулировки исправлены в `docs/installing.md`,
      README и правиле 30 `AGENTS.md`.
65.7. Честное ограничение: в пользовательской TCC-базе **нет ни одной записи Accessibility и ни одной
      записи Maccy**, поэтому сохранить было нечего — доказательство на уровне механизма. Полный
      сквозной прогон «выдал разрешение → пересобрал → осталось» требует выданного разрешения.
